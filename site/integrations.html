Integrations

Use Breakra wherever your agent works.

The same deterministic engine in your terminal, your agent's tool list, your CI and over HTTP. The local paths are free and send nothing anywhere.

Claude Code

Add the MCP server once; your agent gets the check_openapi_change tool.

Cursor and any MCP client

Most MCP clients take a JSON server entry like this one (in Cursor: ~/.cursor/mcp.json). The server speaks MCP over stdio and needs no key or wallet.

Agent skill

Any agent that can read a URL can follow breakra.dev/skill.md: when to call Breakra, how to pay safely, and how to act on each finding. It's also listed on skills.sh and Tessl.

Give your agentread breakra.dev/skill.md

GitHub Actions

Fail a pull request when its OpenAPI file breaks callers. This is a plain workflow using the CLI; an official GitHub Action is on the roadmap. Exit codes: 0 below --fail-on, 1 at or above it, 2 error (unchecked, never "safe").

Scripts and other CI

--json prints exactly what the hosted API returns, so scripts, pre-commit hooks and other CI systems can read one stable shape. --use limits the verdict to the operations your code calls.

Paying agents (x402)

Agents without Node, or that prefer HTTP, can pay $0.02 USDC on Base per check with x402. No account or API key. Only a 200 is charged; Breakra's own errors never are. Read the payment rules in skill.md before signing.

A stable contract to build on

Versioned

Every result names its engine_version and rule_set_version. Classification changes bump the rule set; response-shape changes bump the engine.

Deterministic

The same inputs give the same findings and the same analysis_id, locally and hosted, so a result can be kept with the change that caused it.

Stable values

verdict: safe · review · block. compatibility: breaking · potentially_breaking · unknown · compatible · non_contract. Each finding has a stable rule id (RULES.md).

Fails closed

Invalid or unsupported input is an error with a JSON error.code, never a verdict. unknown is never treated as safe.

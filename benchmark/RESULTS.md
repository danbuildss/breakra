## Curated scenarios (expected outcome vs Breakra)

| Scenario | Expected | Got | Pass | Why it matters |
|---|---|---|---|---|
| An inline enum inside anyOf is moved to a shared component that adds a value. | safe | safe | ✅ | A common refactor that only widens the request; found by Orric on OpenAI's images endpoints (D-050). |
| API-key authentication becomes required for every operation. | review | review | ✅ | Unauthenticated callers will be rejected (Breakra is stricter than oasdiff here, by design). |
| Only a description changes. | safe | safe | ✅ | Documentation doesn't change the contract. |
| A new operation GET /customers. | safe | safe | ✅ | Additive. |
| An operation (POST /orders) is removed. | block | block | ✅ | Callers of a removed operation fail: the only certain break. |
| A value inside a schema's example object changes. | safe | safe | ✅ | Examples are documentation; found by Orric on OpenAI's spec (D-050). |
| The response schema becomes an external $ref. | review | review | ✅ | External refs are never fetched; the change can't be cleared as safe. |
| `total` keeps its name but changes from number to string. | review | review | ✅ | A same-name field with a new type breaks typed clients (raised on X by @sreecharantwts). |
| The new contract is not a valid OpenAPI document (paths is a list). | error INVALID_SPECIFICATION | error INVALID_SPECIFICATION | ✅ | Must fail closed: an error, never a verdict (raised on X by @Steven7FGC). |

| Two OpenAPI 3.1.2 documents; one operation added. | safe | safe | ✅ | 3.1.2 is a clarification-only patch with no new keywords, so the 3.1 rules apply (D-050). |
